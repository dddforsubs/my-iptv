# My IPTV — эталонный список каналов

> **Назначение:** это список **желаемых каналов**, а не каталог работающих URL. Отсутствие потока не является основанием удалять канал из эталона.
> **Источники потоков:** публичные прямые потоки из [`iptv-org/iptv`](https://github.com/iptv-org/iptv) и альтернативные URL из других публичных GitHub-репозиториев, переданные через Google Sheets и прошедшие техническую проверку. Таблица — каталог кандидатов; состав каналов и их порядок задаются этим README.
> **Запрещено:** частные IPTV-аккаунты, логины, пароли, персональные ключи доступа, DRM и источники, для которых потребуется обход авторизации или ограничений доступа.
> **Основа:** фотография избранного от 10.11.2026 + последняя доступная локальная сборка плейлиста от 10.11.2026 (47 M3U-записей) + согласованная подборка качественных детских каналов для возраста 4–5 лет. Проверенный удалённый `docs/playlist.m3u` на 10.11.2026 содержал 35 записей: это *публикуемый результат*, а не полный эталон желаемого.

2. Сохранять две группы в плейлисте: `Детские RU` и `Kids EN`; детский раздел не смешивать с познавательными и новостными каналами.

4. Возрастная пригодность оценивается по назначению канала, **не гарантирует пригодности каждого отдельного выпуска**; это не заменяет родительского контроля.
5. Использовать прямые URL из `iptv-org` и точные кандидаты Google Sheets только после проверки безопасности URL и HLS-цепочки. Не считать DASH `.mpd` совместимым с Televizo без отдельной поддержки.

При отсутствии проверенной замены оставлять прежний URL как непроверенный fallback и указывать причину в статусе и `errors.md`.
7. Не путать детский **Minimax CEE** с `MiniMax Мегамир HD` из раздела 1. Первый не включён в эту подборку без отдельного согласования.

## 4. Принципы актуализации

1. **Эталон неизменен без согласования.** `README.md` — перечень желаемых каналов. `docs/playlist.m3u` — генерируемый перечень найденных источников, включая те, что не прошли техническую проверку; `docs/status.json` — список совпадений, отсутствующих источников и результатов проверки.
2. Сопоставлять потоки `iptv-org` по ID канала и feed из API (`channels.json`, `feeds.json`, `streams.json`). Кандидаты Google Sheets сверять по точному названию с эталоном; не добавлять каналы только по строкам CSV. Читать **все три таблицы приоритетов A, B, C** в данном README.
3. Предпочтения: русский звук для русскоязычных каналов, HD/1080p при возможности, точная версия CEE для Viasat. Изменение региона или языка — это **альтернатива**, а не замена того же канала.
4. Альтернативный URL из другого публичного GitHub-репозитория допустим только после загрузки через опубликованный CSV и собственной технической проверки. Не принимать HTTP 200 за гарантированно воспроизводимый поток. Отдельно проверять геоблокировки и пометки `Not 24/7`.
5. Не удалять канал из эталона из-за отсутствия потока или отказа проверки. В плейлист включать только кандидата с успешной технической и, для рискованных источников, контентной проверкой. Не возвращать отказавший предыдущий URL как fallback; оставить канал в эталоне, отметить отсутствие проверенного источника в `docs/status.json` и добавить причину в `errors.md`.
6. Не подменять `MiniMax Мегамир HD` европейским `Minimax`; название позиции 17 — `MiniMax Микромир`, его точный feed нужно сопоставить отдельно.
7. Сохранять стабильный URL GitHub Pages: `https://dddforsubs.github.io/my-iptv/playlist.m3u`.
8. Публикация M3U должна выполняться **GitHub Actions** по расписанию (раз в сутки) и по `workflow_dispatch` (ручной запуск). ChatGPT Tasks, если включены, могут независимо отслеживать исключения, но не заменяют публикацию и не считаются механизмом записи в GitHub без права на запись.
9. Изменять список желаемых каналов только по явному решению владельца. Ежедневная задача обновляет **потоки и статус**, а не состав эталона. Отдельные альтернативные feed допускаются лишь по описанным для канала правилам.

## 5. Связанные файлы

- `README.md` — данный эталон и правила.
- `errors.md` — накопительный журнал отказов технической проверки; новые результаты добавляются в конец, предыдущие записи сохраняются.
- `scripts/update_playlist.py` — генератор, читающий **все три таблицы README**, подбирающий источники из `iptv-org` и проверенные кандидаты Google Sheets, затем проверяющий HLS-плейлист, медиаплейлист, ключи и первые сегменты без авторизации.
- `scripts/ai_candidates.py` — безопасное чтение опубликованного CSV-каталога; таблица не меняет эталон каналов.
- `docs/playlist.m3u` — публикуемый плейлист для Televizo.
- `docs/status.json` — состояние поиска, отсутствующие потоки и результат технической проверки.
- `docs/candidate_validation.json` — результаты проверки каждого реально опробованного URL.
- `docs/status.json` и `docs/candidate_validation.json` содержат URL в `quarantined_urls`/состоянии карантина, если поток показывает рекламную заглушку или содержимое нельзя подтвердить. Кандидаты проверяются заново при следующем почасовом запуске; успешная повторная проверка снимает карантин автоматически.
- Домен `cinerama.uz` — только сигнал повышенного риска. Для доступного потока генератор дважды извлекает кадр FFmpeg и ищет маркеры CINERAMA через Tesseract; совпадение или невозможность проверить оба кадра помещает конкретный URL в карантин. Остальные кандидаты того же точного канала продолжают проверяться по обычным техническим правилам. Без FFmpeg/Tesseract такой кандидат остаётся непроверенным и не публикуется.
- `.github/workflows/update-iptv.yml` — ежедневный и ручной запуск генератора, тесты, коммит плейлиста, статуса и накопительного отчёта, затем деплой GitHub Pages.
- `tests/` — проверки парсинга эталона, правил языка/региона, дедупликации и защиты от массовой потери каналов.

> **Важно:** старые `config/favorites.m3u` и `config/extra_watch.json`, если они будут обнаружены в репозитории, нельзя использовать как независимый второй эталон. Генератор должен читать `README.md` напрямую либо использовать автоматически создаваемую из него конфигурацию. Нельзя считать перечисленные выше файлы уже созданными, пока это не подтверждено GitHub.
